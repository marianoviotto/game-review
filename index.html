How Game Review works

Game Review builds the play-by-play part of the IFAF game review sheet while you watch the game, and lets the officials replay the review with every remark in place.

Purpose

IFAF video supervisors comment on selected plays: the timecode, a link to that moment, the play type, the position or positions involved, the rule or situation, a grade and a written comment. Typing timecodes by hand and switching between the video and the spreadsheet is slow and error prone. This tool reads the timecode straight from the player, keeps the categories of the review sheet as fixed choices, and copies everything back into the sheet in its own column order.

It is a companion to Game Pace and works the same way: same look, same player controls, same backups. The two are separate tools for now.

Reviewer workflow

Load the game, set the game start, and watch. When a play deserves a remark, press M: the video pauses and a new play opens in the form with the current timecode. Choose Rules or Mechanics, one or more positions, the application code when it applies (usually for Rules), the grade, and write the comment. Ctrl + Enter saves. To remark on a second official in the same play, use Save + same play: it saves and opens a new remark with the same timecode, play type and half.

Every play in the list can be edited or deleted. Edit loads it back into the form; while editing you can move it to the current video time. Delete has a short undo window. The position filter above the list shows the remarks for one official, together with the ones addressed to the whole crew, which helps when writing the notes for each position.

Game details (reviewer, supervisor, date, crew) and the general and per-position notes live at the bottom of the page. Reviewer and supervisor are remembered for the next game.

Full screen and zoom

Full screen uses the tool's own frame, not YouTube's, so the zoom and the comments over the video keep working. YouTube's own full screen button is turned off for that reason. Marking a play in full screen leaves full screen so the form is visible.

The page cannot read the pixels of a YouTube video, so the zoom enlarges the whole player around the mouse instead of using a lens. The result is the same to the eye. Sharpness depends on the resolution of the video: use YouTube controls to raise the quality when you need detail.

Export to the review sheet

Plays. Copy places the plays on the clipboard as columns A to G of the Game Review sheet, in time order, ready to paste at A19. Column B is a self-contained link formula to that second of the video, so it works no matter how column A is formatted. The scope selector copies everything with an END OF HALF row between halves, or only one half, for templates where the END OF HALF row is already in place. Line breaks inside a comment are turned into spaces so each play stays on one row.

Game details and notes. Copy for column B places 16 lines ready to paste at B1: reviewer, supervisor, game link, start time, date, the four crew names in rows 7 to 10, and the general and per-position notes in rows 12 to 16. Rows 6, 11 and the tempo block in columns D and E are not touched.

Official view

The official view is the same tool opened with ?view at the end of its address. The officials keep receiving the review sheet as usual; the review file you download with Backup, together with the official view link, lets them replay the whole review. They open the link, load the file, and the video comes back with every play in the list, the notes, and the current remark next to the player.

By default the video pauses when it reaches each remarked play and shows the comment over the image, also in full screen. Both can be turned off. The official view is read only: nothing can be edited or exported from it, and the last review loaded stays available in that browser.

Assumptions and limitations

The categories (play type, positions, application codes and grades) mirror the review sheet in use in October 2026. Changing them requires a code change, described below.

Some channels disable playback outside YouTube; local file mode plays a downloaded copy with the same tools, but the copied links then have no video address. Since 2025 YouTube rejects embedded players on pages without a web origin, so the tool must be opened from its published address and not from a file on disk.

Reviews are stored in the browser where they were made. Backups are the way to move them to another computer or hand them to someone else.

Data model and storage

Each review is a session keyed by its video, as in Game Pace.

{
  "key": "yt:-1iW9TCiZA0",
  "src": { "kind": "yt", "id": "-1iW9TCiZA0", "url": "https://www.youtube.com/watch?v=-1iW9TCiZA0" },
  "start": 338,             // game start in video seconds, or null
  "half": 1,                // half applied to new plays
  "info": { "reviewer": "", "supervisor": "", "date": "",
            "crew":  { "R": "", "DJ": "", "FJ": "", "SJ": "" },
            "notes": { "general": "", "R": "", "DJ": "", "FJ": "", "SJ": "" } },
  "entries": [
    { "id": "m1x2y3", "t": 339.4, "half": 1,
      "type": "Rules",      // Rules | Mechanics
      "pos": ["DJ","SJ"],   // R DJ FJ SJ BJ C (C = Crew)
      "app": "ICD",         // Rule Key code, or "" when none
      "grade": "NC",
      "comment": "…",
      "marks": [] }         // reserved for drawings over the video
  ]
}

Sessions are saved in localStorage under review:<key>, the last one opened under review:last, reviewer settings under review:settings, and the review loaded in the official view under review:viewer. A backup wraps the session as {"app":"ifaf-game-review","v":1,"session":{…}}. The marks list is empty in this version and is kept so that drawings can be added later without breaking older review files.

Changing or extending it

The categories live in four constants at the top of the script: POS for positions, GRADES for grades with their meaning and whether they read as positive, negative or neutral, FOULS and SITUATIONS for the application codes of the Rule Key. Keep existing IDs when renaming labels, so saved reviews still load. If the session format changes, increase the backup version and keep the loader able to read older files.

Before publishing a change, check by hand: marking a play and saving it, two remarks on the same play, editing and retiming, delete and undo, reopening the page, both copy buttons pasted into a copy of the review sheet, and a backup loaded in the official view.
